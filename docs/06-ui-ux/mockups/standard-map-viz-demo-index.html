Map visualization · Standard Map redesign

How should connections look on the map?

Five connection-map styles. Each demo shows the map panel alongside a connection table / briefing strip — you always get both, not one or the other. Pick a primary map style (and optional secondary).

Product rule: Map view is a lens, not the only output. Every layout includes: (1) connection map, (2) sortable connection index, (3) selected link detail. Switch map style without losing table context.
1

Tier Hierarchy (top-down)

Core → Distribution → Access in fixed horizontal bands. Orthogonal links. Matches mental model of campus design.

Best for NOC daily view
2

Radial Hub (core-centric)

Core at center; dist ring; access on outer ring. Good for “what hangs off this core?”

Best for NetEng design review
3

Schematic Orthogonal (Visio-style)

Clean 90° lines, port labels on hover, bundle icons for Po/vPC. Print and change-record friendly.

NOC handoff + NetEng docs
4

Neighborhood Focus (1–2 hop)

Only selected device + immediate neighbors. Reduces hairball on large sites. Syncs with table row click.

Best for NOC troubleshooting
5

Matrix / Adjacency Grid

Devices on both axes; cell = link exists. Spot orphans, asymmetry, missing return CDP.

Best for NetEng audit / validation

Network engineering team recommendation

  • Default map for most users: Viz 1 (Tier Hierarchy) — NOC sees structure instantly; table below answers port-level questions.
  • Troubleshooting toggle: Viz 4 (Neighborhood) — same data, less clutter when chasing one uplink or access switch.
  • Export / change packet: Viz 3 (Schematic) — matches traditional diagrams in runbooks.
  • Design / audit session: Viz 2 (Radial) or Viz 5 (Matrix) — core dependency and symmetry checks.

Ship as map style selector in Standard Map: Tier | Radial | Schematic | Focus | Matrix — all sharing one connection index.
